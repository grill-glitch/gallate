# Shell Layer Examples

Worked project layouts for the gallate Shell layer. Each example is a
**complete project tree** as it would appear on disk after `init` (and
post-init editing).

These are **reference projects** — not runnable binaries. They show
what a real gallate project looks like so CLI authors can copy and
users can recognize the layout.

---

## Layout

```text
shell-layer-examples/
├── README.md
├── minimal-project/
│   ├── gallate.yaml              # created by `init` with -i -o --media text
│   ├── .meta.json                # CLI-maintained project state
│   ├── text/                     # empty placeholder; engine will populate on -e
│   └── image/                    # empty placeholder
└── full-project/
    ├── gallate.yaml              # full configuration with engine options
    ├── .meta.json                # CLI-maintained project state (intentionally separate from gallate.yaml)
    ├── text/  image/
    ├── audio/  video/  font/    # engine-extension directories (empty)
    ├── scripts/
    │   ├── unpack.py             # pre script
    │   └── repack.py             # post script
    └── engine-options.md         # what --engine.* keys this CLI accepts
```

See [`docs/shell-layer/13-meta-json.md`](../docs/shell-layer/13-meta-json.md)
for the `.meta.json` design.

---

## minimal-project

A bare-bones gallate project. Generated by:

```bash
tool init ./my-game \
  --input ./game.pfs \
  --output ./game-zh.pfs \
  --media text,image
```

The `text/` and `image/` directories exist as empty placeholders;
the CLI will populate them on first `-e`. See
[`minimal-project/gallate.yaml`](./minimal-project/gallate.yaml).

---

## full-project

A complete gallate project. Demonstrates:

- All standard YAML top-level keys
- Pre / post scripts
- Engine-extension sub-media (`audio.includes` / `excludes`)
- An engine extension option (`text_encoding`)
- Engine-extension media directories (`audio/` / `video/` / ` font)

See [`full-project/gallate.yaml`](./full-project/gallate.yaml) and
[`full-project/engine-options.md`](./full-project/engine-options.md).

## Using them as a template

CLI users SHOULD:

1. Copy `minimal-project/` first.
2. Verify `tool -e ./gallate.yaml` and `tool -i ./gallate.yaml` work
   against a real game file.
3. Add engine options as needed (consult the engine's `tool --help`).
4. Move to a richer layout only when scripts or extra media are
   actually needed.

CLI authors SHOULD:

1. Use `minimal-project/` as the seed when implementing `init`.
2. Make sure `init --input X --output Y --media text` writes exactly
   the YAML shown in the minimal example.
3. For engines that expose audio/video, make `init` produce a layout
   that matches the full-project structure.
