# 06. Project Structure

> Status: **Normative**. Defines the standard layout produced by
> `init`, and the rules for engine extension directories.

---

## 6.1 Standard layout

```text
my-game/
├── gallate.yaml
├── text/
├── image/
├── audio/                # engine-extension (audio)
├── video/                # engine-extension (video)
└── scripts/
```

`text/` and `image/` are the standard directories — present for any
gallate CLI.

`audio/` and `video/` are **engine-extension** directories, created
when the engine exposes audio/video as media. Engines that don't
handle these skip them entirely.

`scripts/` holds user-defined pre/post scripts.

---

## 6.2 Engine extension directories

A CLI MAY add its own directories on top of the standard layout.
For example, a Ren'Py CLI might create `audio/` and `font/`:

```text
my-game/
├── gallate.yaml
├── text/                # standard
├── image/               # standard
├── scripts/             # standard
├── audio/               # engine extension media (voice acting)
├── video/               # engine extension media (cutscenes) — optional
├── font/                # engine extension media (TTF/OTF)
└── portrait/            # engine extension sub-media
```

These extra directories are engine choices; the standard CLI does not
require them.

---

## 6.3 Layout invariants

Regardless of extensions, the following are always true:

- `gallate.yaml` is the single Project Target. It MUST exist at the
  Project Root for any non-init operation.
- The standard directories `text/` and `image/` MAY be present even
  when empty (or absent if the engine never touches that media).
- Pre/post scripts live under `scripts/` by convention, but the
  path in `gallate.yaml` may be anywhere relative to the Project
  Root.

---

## 6.4 Generated by `init`

`init` is the canonical way to produce a standard layout. See
[07-init.md](./07-init.md).

A project created by `init` MUST contain:

```text
my-game/
└── gallate.yaml           # at minimum; standard directories are optional
```

`init` MAY create the standard directories; this is engine-specific.
A user MAY add them by hand.

---

## 6.5 When the user edits

A user editing the project is free to:

- Add new directories.
- Delete unused standard directories.
- Move pre/post scripts elsewhere (just update `gallate.yaml`).

The CLI MUST NOT assume any directory beyond `gallate.yaml` exists.
It MUST create missing directories lazily when writing output.

---

## 6.6 Relation to media

The standard directories map to the standard media:

```text
text/   ↔  -t
image/  ↔  -i
```

Engine-extension media MAY have their own directory:

```text
audio/   ↔  -a   (when the engine exposes audio)
video/   ↔  -v   (when the engine exposes video)
font/    ↔  --engine.font   (typical; not a media flag)
```

But this is **a convention, not a rule.** The CLI decides where each
media's output goes. Engines MAY flatten all media into one output
directory, or use a deeper per-resource tree.

---

## 6.7 What lives where — summary

```text
my-game/                            (Project Root)
├── gallate.yaml                    (Project Target, required)
├── text/  image/                   (standard media dirs, optional)
├── audio/  video/  font/           (engine-extension dirs, optional)
├── scripts/                        (convention for pre/post scripts)
└── <engine-extension dirs>/        (engine-specific, optional)
```

The standard CLI MUST accept any project that satisfies the top two
rows; engines MAY add more.
